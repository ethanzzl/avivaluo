# Project Decisions

本文件记录 Avivaluo-Web 已确认的重要产品、设计与技术决策。

目的：

* 防止后续任务重复讨论已经确定的问题
* 防止新对话或新修改无意推翻已有方向
* 给 Codex 提供长期稳定的判断依据

本文件只记录长期有效决策。

不记录：

* 一次性任务
* 临时 Todo
* 已完成的 QA
* 单次视觉验收结果
* 纯历史过程

如果用户新的明确要求与本文件冲突：

**以用户当前明确要求为准，并根据需要同步更新本文件。**

---

## 1. 网站定位

### 决策

Avivaluo-Web 是 Aviva大双的中英双语插画师个人作品集网站，同时承担商业合作入口。

网站的核心目的：

* 展示代表作品
* 展示商业应用能力
* 建立专业信任
* 帮助潜在品牌理解创作方向
* 促进合作咨询

首要转化目标：

**发起合作 / Start a Project**

次要转化目标：

**查看作品 / View Work**

### 原因

该网站不是单纯的个人图片档案，也不是 SaaS、企业后台、电商或通用营销站。

---

## 2. 作品优先

### 决策

网站设计始终优先服务作品展示。

长期优先级：

**作品 > 视觉质量 > 用户体验 > 性能 > 可维护性 > 额外功能 > 技术炫技**

### 原因

网站的核心价值来自插画作品本身，而不是界面复杂度或技术表现。

---

## 3. 真实作品比例优先

### 决策

不同作品不强制统一成相同图片比例。

应优先保留：

* 原始构图
* 原始比例
* 作品主体
* 作品文字
* 原有签名

只有在封面或明确布局需求下允许裁切，并且必须检查焦点。

### 原因

插画作品的构图差异较大，强制统一比例会削弱作品本身的展示效果。

---

## 4. 作品页保持编辑感

### 决策

作品详情页采用编辑式、作品集式的页面体验。

不将所有图片机械地装进统一卡片。

允许根据：

* 横图
* 竖图
* 方图
* 内容节奏

形成不同的页面排布。

### 原因

作品页应更接近编辑出版物或专业作品集，而不是图库后台或电商列表。

---

## 5. 留白属于设计

### 决策

页面留白是主动设计的一部分。

不得因为页面存在空白就自动增加：

* 卡片
* 装饰
* 文案
* CTA
* 边框
* 图形
* 背景元素

### 原因

克制的界面能让插画获得更多视觉空间。

---

## 6. 不采用模板化 SaaS 风格

### 决策

默认避免以下视觉模式：

* 大量功能卡片
* 模板化 Feature Section
* 玻璃拟态
* 紫蓝渐变
* 重阴影
* 过量圆角
* 大量 Badge
* 无意义浮层
* 过度 Dashboard 化
* 装饰性数据模块

### 原因

这些模式容易让网站偏离插画师个人作品集的编辑感与品牌辨识度。

---

## 7. 色彩保持克制

### 决策

UI 色彩保持克制，作品本身承担主要色彩表达。

新增颜色前，优先检查：

* 现有设计令牌
* 当前主色
* 当前强调色
* 作品本身是否已经提供足够视觉变化

不因局部页面显得简单就随意新增颜色。

### 原因

插画作品已经具有丰富色彩，UI 颜色过多会与作品争夺注意力。

---

## 8. 当前视觉方向

### 决策

当前网站的气质、留白和比例仍参考：

`design-references/homepage-direction-v3.png`

该文件用于校准：

* 页面气质
* 留白
* 比例
* 视觉节奏

首页具体结构已由第 25 条的纯作品墙决策替代，不再沿用参考图中的首屏介绍与合作方向区块。

不得将参考图直接作为网页背景或切片实现。

### 原因

参考图用于定义方向，不应成为实际网页资产。

---

## 9. DESIGN.md 的角色

### 决策

`DESIGN.md` 是本项目当前视觉与体验方向的主要文档。

涉及以下修改时应优先参考：

* 页面布局
* 字体
* 留白
* 色彩
* 图片节奏
* 导航
* 动效
* 响应式视觉行为

如果用户新的明确要求与 `DESIGN.md` 冲突：

优先执行当前明确要求，并在必要时更新 `DESIGN.md`。

## 10. 双语结构

### 决策

中文为默认语言。

英文使用 `/en/` 路径。

中英文页面：

* 共享组件
* 共享项目关系
* 共享结构化内容来源

不维护两套独立视觉实现。

英文按英文读者习惯重写，不逐字硬译。

语言切换应尽量停留在当前页面或当前项目。

### 原因

这样可以避免：

* 双语内容失配
* 两套页面逻辑重复
* 后续维护成本增加

---

## 11. 当前技术栈保持不变

### 决策

当前正式网站继续使用：

* Next.js 16
* React 19
* TypeScript
* 原生 CSS
* CSS Variables
* GitHub
* Vercel

未经用户明确批准，不迁移核心技术栈。

### 原因

当前技术栈已经能够满足作品集网站的功能与维护需求，没有必要为了技术展示增加迁移成本。

---

## 12. 减少客户端 JavaScript

### 决策

公开内容页面尽量减少客户端 JavaScript。

优先使用：

* 静态生成
* Server Components
* CSS
* 浏览器原生能力

只有实际交互需要时才增加客户端逻辑。

### 原因

项目核心是内容与作品展示，不需要复杂 SPA 运行成本。

---

## 13. 内容数据集中维护

### 决策

中英文项目与页面内容继续采用统一结构化数据维护。

当前主要内容来源：

`app/site-data.ts`

不将长篇项目内容散落在大量组件中。

### 原因

这样可以降低：

* 双语失配风险
* 内容维护成本
* 重复代码

---

## 14. 图片母版与网页衍生图分离

### 决策

原始插画母版不直接作为网页资源。

长期规则：

* 原始来源保存在 `source-assets/`
* 网页使用处理后的衍生文件
* 不直接覆盖母版
* 不直接将母版放入 `public/`

### 原因

这样可以同时保护：

* 原始素材
* 网页性能
* 发布安全
* 后续重新生成能力

---

## 15. 图片保护策略

### 决策

当前图片保护以“降低直接取用便利度”为目标，而不是声称完全防下载。

允许采用：

* 网页衍生图
* 限制公开分辨率
* WebP 等网页格式
* EXIF 版权信息
* 关闭原生拖拽
* 版权提示
* 个别完整作品添加轻量署名

不采用：

* 全站重水印
* 屏蔽右键
* 破坏正常浏览和可访问性的方式

### 原因

任何网页图片都无法真正完全阻止截图或开发者工具保存。

---

## 16. 当前公开联系方式

### 决策

网站当前公开：

* Email
* 小红书
* Instagram

当前不公开：

* 微信
* 电话

在没有真实接收端前，不制作看似可以提交的联系表单。

## 17. 内容真实性优先

### 决策

不得为了让网站显得更完整而编造：

* 客户
* 项目年份
* 项目背景
* 职责
* 成果
* 数据
* 奖项
* 评价
* 报价
* 合作反馈

无法确认的内容：

* 标记为 `待确认 / To be confirmed`
* 或不公开展示该字段

### 原因

商业作品集的可信度比“信息看起来完整”更重要。

---

## 18. 当前核心产品范围

### 决策

当前核心网站范围：

* 首页
* 作品列表
* 作品详情
* 关于
* 联系
* 隐私
* 404

以下功能默认不进入当前阶段：

* 博客
* CMS 后台
* 在线支付
* 在线预约
* 账号系统
* 会员系统
* 复杂筛选
* 站内搜索
* 重型动画
* 3D
* 自动播放媒体

### 判断标准

新增功能前优先判断：

**它是否帮助潜在合作品牌理解作品、建立信任或发起合作？**

如果不能，默认不进入核心范围。

---

## 19. 最小必要修改

### 决策

项目维护优先采用：

**最小必要修改原则。**

局部问题通常使用局部修复。

不要因为一个小问题顺便：

* 重构整个页面
* 重写组件体系
* 调整目录
* 替换 CSS 系统
* 更换技术方案
* 增加额外功能

### 原因

网站当前已经上线，稳定性和可控修改成本优先于代码形式上的“更漂亮”。

---

## 20. 视觉修改必须实际验收

### 决策

视觉任务不能只以 Build 通过作为完成标准。

重要视觉修改应实际检查：

* Desktop
* Mobile
* 图片比例
* 页面留白
* 横向溢出
* Console
* 关键交互

并根据需要对照 `DESIGN.md`。

### 原因

代码正确不等于视觉正确。

---

## 21. 响应式是长期要求

### 决策

关键布局修改至少考虑：

* 360px
* 768px
* 1024px
* 1440px

重点关注：

* 图片比例
* 文字换行
* 导航
* 留白
* 横向溢出
* 触控区域

桌面端正常不能代替移动端验证。

---

## 22. 不用 AI 图片冒充作品

### 决策

网站不得使用：

* 随机图库
* AI 生成图片
* 临时代替素材

冒充 Aviva大双真实作品。

如果使用非作品类辅助视觉，也必须明确其性质。

### 原因

网站是个人作品集，真实性是品牌可信度的一部分。

---

## 23. 历史 QA 不作为当前事实

### 决策

归档的：

* QA 报告
* 截图
* 历史验收
* 旧版本审阅

仅作为历史参考。

不得因为过去某次测试通过，就默认当前版本仍然：

* 无 Bug
* 无横向溢出
* 无 Console Error
* 满足所有响应式要求
* 满足所有性能或可访问性目标

### 原因

项目状态会持续变化，历史验证不能替代当前验证。

## 25. 首页采用纯作品墙与纯白背景

### 决策

首页在导航之后直接展示当前 8 个已发布项目的封面：

* 按真实比例组成三列、两列、一列的响应式作品墙
* 不设置介绍型 Hero
* 图片下方不显示项目名称、分类或介绍
* 桌面端可通过悬停显示克制的项目名称与分类提示；触屏端只显示图片
* 不设置独立的“合作方向”区块，也不在导航中显示该入口
* 品牌字标承担返回首页的功能，导航不重复显示“首页 / Home”
* “浏览插画风格与顾客肖像”放在首页结尾合作 CTA 下方
* 网站基础背景使用纯白色

### 原因

让作品成为首页的第一层信息，减少介绍性内容对连续浏览的打断，同时在页面结尾保留清晰的合作转化入口。

---

## 26. 最终原则

Avivaluo-Web 的长期目标不是增加越来越多功能。

核心目标始终是：

**让 Aviva大双的插画作品以更专业、更清晰、更有辨识度的方式被潜在合作品牌看到，并降低从“看到作品”到“发起合作”的阻力。**
